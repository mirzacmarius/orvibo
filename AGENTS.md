# Agents

Read `README.md` first: it describes the repo layout, the scripts and how the site
deploys. This file adds what an agent needs on top of that.

## What matters in this repo

- `apps/web` is the only deployed app: the ORVIBO site at https://www.orvibo.ro
  (port 3001 in development, start it with `bun dev:web`).
- `apps/app` (port 3000), `packages/backend` (Convex) and `packages/email` are
  leftovers from the Create v1 starter. They are not deployed and the site does
  not import them. Do not wire the site to Convex.
- Bun 1.3.14 is the package manager (`packageManager` in `package.json`). Do not use
  npm, yarn or pnpm, and keep `bun.lock` in sync (`bun install`).

## Before you push

Run the same checks as CI (`.github/workflows/check.yml`):

```bash
bun install --frozen-lockfile
bun run lint
bun run typecheck
bunx turbo run build --filter=@v1/web
```

The web build needs no environment variables. If `tsc` reports missing modules
under `apps/web/.next/types` after you delete a route, remove `apps/web/.next`
(those types are generated by the previous build).

## Environment

- `apps/web` reads only optional variables: `NEXT_PUBLIC_ORVIBO_ASSETS_URL`,
  `ORVIBO_ASSETS_ORIGIN` and `NEXT_PUBLIC_OPENPANEL_CLIENT_ID`. See the README.
- `apps/app` validates its env with `@t3-oss/env-nextjs` and needs
  `NEXT_PUBLIC_CONVEX_URL`. Turborepo runs in strict env mode, so
  `SKIP_ENV_VALIDATION` does not reach `next build` when you run it through turbo.
- The Convex backend dev script (`packages/backend/scripts/convex-dev.mjs`) needs an
  interactive login or `CONVEX_DEPLOY_KEY`; without either it skips and exits 0.

## Gotchas in `apps/web`

- **Copy** belongs in `src/app/[locale]/dictionaries/en.json`, read through the
  helpers in `dictionaries.ts`. Run `bun run orvibo:extract-i18n` to refresh the
  CN/global source report in `dictionaries/i18n-extract-report.json`.
- **Products.** A product page is registered in `src/lib/orvibo/products/registry.ts`.
  Slugs the menus link to without a page live in `products/upcoming.ts` and render a
  noindex "coming soon" page; every other slug is a 404. Keep the two lists in step
  with the links in `SiteHeader.tsx`, `SiteFooter.tsx` and the home page.
- **Placeholder pages** use `PLACEHOLDER_ROBOTS` from `src/lib/orvibo/site.ts` and are
  left out of `src/app/sitemap.ts`. Remove the first and add the second when a page
  gets real content.
- **Root font size.** `src/styles/orvibo.css` sets `html { font-size }` to mimic the
  original site's rem layout: 75px below 1360px wide, 100px around 1760px, and
  `83.34vw / 16` above 1920px (about 133px at 2560px). Any rem-based Tailwind or
  shadcn default (`p-6`, `gap-4`, `text-sm`, `max-w-sm`) is therefore at least 4–6
  times larger than usual, and more on wide screens. Use pixel values (`p-[24px]`)
  for chrome, or `calc(var(--orvibo-rem-scale)*N)` for sections that should scale
  with the viewport.
- **Link colours.** `.orvibo-site a { color: inherit }` beats single-class utilities
  on an anchor, so `text-*` classes on a link have no effect. Put the colour on the
  link's parent element instead.
- **Media paths** go through `assetUrl()` in `src/lib/orvibo/assetUrl.ts` so they can
  be served from R2. Upload new media with `bun run orvibo:upload-r2` (needs the R2
  credentials described in `apps/web/.env.example`).
